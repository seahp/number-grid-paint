# 版面解算器（layout solver）

这一份讲"格子到底多大是谁决定的"。它不是查表，是**在真浏览器里量出来的**——
所以任何改动都要用 `scripts/size_probe.py` / `width_probe.py` 回归，不能只靠 `node --check`。

## 1. 一句话原理

A4 版心是固定的（210×297mm，页边距后约 184×265mm 可用）。
盘面、页眉、集章表、页脚、说明五块要在这一个盒子里排好且不溢出。
解算器做的事：**给每格一个上限 → 二分往下收 → 收到这张纸刚好装得下为止**，
同时允许在三个"紧张度"档里各试一遍，最后按"先别挤孩子写字、其次格子最大"挑一档。

## 2. 上限从哪来（`cellCeil`）

| 情形 | 10×10 | 8×8 | 瓶颈 |
| --- | --- | --- | --- |
| 一页一卷 | 17.4mm | 21.2mm | 版心宽度 179mm（184 − 5mm 行号列） |
| 半页·集章表在右 | 9.8mm | 12.3mm | 宽度只剩 104mm（184 − 4 − 76） |
| 半页·集章表压下面 | 9.0mm | 11.0mm | 高度 |
| 半页·不勾集章表 | 13.0mm | 16.0mm | — |

字号跟着格子走：`fontFor(c) = clamp(8pt, 22pt, 1.15×c)`，格子放大数字同步放大，
一年级才真的看得清、好下笔。

## 3. 三档紧张度（`STG`）

* **0** — 说明单栏大字 + 集章表常规栏数。
* **1** — 说明换两栏 + 集章表多分一栏 + 页眉压成一行。栏数仍受"并格后这一格写不下
  `quota` 条就少分一栏"约束。
* **2** — 允许破那条约束，换最后的版面空间。

挑档不是"哪档格子最大用哪档"，而是**够用就不挤**：先算这套版面最多能拿到多大格子
（`best`），再按 0→1→2 回头看，哪一档离 `best` 差不到 **1mm** 就停在那一档。
1mm/格摊到整盘才 10mm，孩子看不出，但 9pt 单栏说明明显好读。差得超过 1mm 才真算"挤"。
半页（`per=2`）一律用一行式页眉，因为 133mm 高度放不下两行。

## 4. 判据与噪声底（为什么不能只看"溢出=0"）

`overPct()` 返回当前版面还挤多少 mm（负数=有余量）。装得下的判据是
`over <= TOLF`，而 `TOLF = max(OVER_TOL, min(FLOOR_OVER + 0.05, 1.0))`：

* `FLOOR_OVER` 是**这台浏览器的噪声底**：先把格子砸到 5.6mm 下限再量一次，
  这时格子驱动的溢出基本收干，剩下的就是表格线、行高、页脚外边距的取整量
  （±0.1～0.3mm），而且**与格子大小无关**。
* 不放宽就会二分"永远找不到能装下的那一档"，数表直接砸到下限。
  2026-11-13 用户在 Safari 里看到的"每格 5.6mm + 版面仍挤 0.1mm、Edge 里正常"就是这条。
* 上限只认 1mm：再大就不是取整噪声而是真装不下，那种情况照旧压格子 + 红字报警，
  而不是把 2mm 的内容顶到纸边上。

5.6mm 是格子下限（再小一年级写不动），到下限还溢出就报警，不硬塞。

## 5. 缩放比也要折算

窄窗口（≤900px）时屏显预览会 `transform: scale(k)` 缩小整张纸。
`getBoundingClientRect` 给的是**缩放后的像素**，`getComputedStyle` 的 padding 是**布局像素**，
混用会凭空多出 `padding×(1−k)` 的假溢出（左右各 6.5mm、上 6mm），而且它跟格子大小无关，
二分怎么收都收不掉 → 盘面砸到 5.6mm、三档全"放不下"、➕➖ 集体失效。
现在 `overBox()` 按 `scaleOf()` 折算，`scripts/width_probe.py 1440 760 400` 就是盯这条：
**窗口多宽都解出同一个格子**（k=1.00 / 0.91 / 0.58 三列 mm 必须一致）。

## 6. 集章表的栏数与并格（`scoreCols` / `eqNeed`）

栏数按"宽度放得下"倒推，而不是只看目标数：

1. 一栏里能摆下 `quota` 个提示格 → 照常一格一对（孩子一格写一条，最舒服）。
2. 摆不下就并成一格：横着能写几条 × 竖着约两行 ≈ 这一格能写几个对，
   写不满 `quota` 个对就少分一栏——只有 STG=2 才破这条。
3. 连提示本身都放不下 → 一定少分一栏。

`eqNeed()` 估"□+□=10 这种提示要占多宽"。系数 **2.95**（每字 mm/pt 折算）是 2026-11-15
用真浏览器量的：把克隆表插进真正的 `.task` / `.task.mini` 里（CSS 才和纸面一致），
量每个 `hintEq` 的自然宽度反推，半页 8pt 最差 2.953、整页 9pt 2.907、tight 8.5pt 2.933。
旧值 2.58 低了 13%——中文版面因为算式格有富余没露馅，英文标签列一宽就顶格了。

列宽写在**表头**上（`table-layout:fixed` 只认第一行）。英文标签列比中文宽
（"Prod 81" 比「积=81」长），多占的宽度由 `scoreCols` 从算式格里扣，
所以英文下同一套设置会少并几格／多分一栏——是版面自己退让，不是硬塞。

## 7. 手动微调（➕ / ➖）

先按自动解算拿到 `CELL_AUTO`（这套版面的自动格子），`S.cellAdj`（−8…+8 mm/格）
是**在自动值上加减**后反解 `FIT`：拿 `want = CELL_AUTO + cellAdj`，在 0.2mm 精度内
找一个真能解出这个格子的收缩量。撞到边界时 `CELL_CLAMP` 记 `'hi'` / `'lo'` / `'floor'`，
状态条用 `T('clampHi')` / `T('clampLo')` / `T('wFloor')` 说人话，而不是把中文哨兵值当控制流。
按钮文字在两种状态间切换（"自动" ↔ "+2mm"），点"自动"回零。**不要**把这个读数做成
行尾独立 span——多那一句这行就宽 110px，➕ 一按就折成四行。

## 8. 改版面时的红线

* 任何字号、内边距、栏宽改动 → 必须重跑 `size_probe`（zh + en）和 `width_probe`。
* 新增"语言相关的宽度差异"要同时更新 `eqNeed` / `Wq` / `miniLayout` 的注释，
  否则下一个人会以为 2.95 是拍的。
* 别在版面代码里写死中文串做控制流。历史上的两个坑：
  `CELL_CLAMP` 曾用 '加不动' / '已到底' / '挤到下限' 当哨兵值，现在换成 `'hi'|'lo'|'floor'`；
  `CUTLINE` 曾是一个模块级中文常量，现在改成 `cutlineHTML()` 每次 `paint()` 重算，
  否则切语言后裁开线还是旧文案。
